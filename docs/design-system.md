## 0. Codex 使用说明与规范优先级

后续 Codex 会话在修改 `apps/web`、公开页面模板、公共样式或用户端交互前，必须完整读取本文件。不得仅依据现有页面的内联 CSS 推断设计标准。

规范优先级如下：

1. 数据真实性、审核边界和来源规则以 `docs/product-design.md`、数据契约及正式事实状态为最高优先级。
2. 用户端视觉、组件、布局、响应式和交互以本文件为最高优先级。
3. 现有页面样式仅代表历史实现，不构成设计规范；与本文件冲突时，应按本文件逐步迁移。
4. 未经明确确认，不得新增品牌色、字体、状态名称、页面布局体系或重要交互模式。

规范词语：

- **必须**：所有相关页面统一遵守。
- **应当**：默认遵守，只有明确业务理由才可偏离，并在变更中说明。
- **可以**：允许的增强项。
- **禁止**：不得实现。

## 1. 目的与范围

本规范统一首页、公开资格信息页、资格目录、年度考试页、报名与条件页、考试内容页、合格率页、日历、比较、更新中心、可信度页面、审核后台和后续数据工具的视觉与交互表达。它服务于“官方事实优先、状态透明、移动端可用”的产品定位。

本规范只定义界面层：颜色、字体、间距、布局、组件、状态、响应式和可访问性。考试日期、费用、报名条件、合格率等内容必须从已批准事实读取，不得由界面层硬编码或推测。

## 2. 设计原则

1. **先给结论，再给来源**：用户先看到当前状态和关键事实，再展开官方来源、确认时间与历史。
2. **可信度可见**：每个动态事实都能说明适用年度、确认时间和来源状态。
3. **信息密度适中**：用卡片、表格和分组标题组织复杂信息，避免长段落堆叠。
4. **状态不靠颜色单独表达**：状态必须同时使用日文文字、颜色和必要的图标或边框。
5. **移动端优先**：窄屏先保证阅读、筛选、来源展开和主要行动，桌面端再增加并列信息。
6. **克制而稳定**：不使用夸张渐变、装饰性动效、虚假评分或制造紧迫感的视觉。
7. **事实层级高于营销层级**：关键日期、资格条件、状态与来源优先于广告、相关文章和增长入口。
8. **少卡片化**：卡片只用于可操作项目、结构化事实和需要边界的模块；普通正文依靠排版和留白分层。
9. **一处规则，全站一致**：相同状态、字段、日期和操作在不同页面使用同一视觉与文案。

## 3. 品牌定位、语气与文案

### 3.1 整体视觉定位

整体定位为：

> 可信数据媒体 × 轻量资格考试工具

视觉关键词为：可信、清晰、克制、透明、结构化、现代日文信息服务。页面应比传统政府网站更易读、更适合移动端，但不能呈现为课程销售页、内容农场或强转化 SaaS 落地页。

视觉比例建议理解为：约 70% 数据与公共信息工具、20% 编辑型内容、10% 友好引导。该比例只用于把握调性，不转化为实际组件数量。

### 3.2 品牌边界

- 品牌标识首发使用简洁文字标识，不依赖复杂 Logo。
- 产品正式名称尚未确定时，使用可替换的文字品牌区域，不把临时标题制作为图片。
- “公式情報”表示信息来自官方来源，不得通过名称、徽章、印章或视觉暗示本站为政府或考试实施机构的官方网站。
- 禁止模仿日本政府机关徽章、印章、公章、官方认证标识或未经许可使用实施机构 Logo。
- 首发不建立深色主题；完整浅色主题是唯一已确认主题。

### 3.3 文案语气

界面默认使用日文；文案简洁、事实性强，避免“必过”“最简单”“绝对推荐”等承诺。官方术语必须保留，例如 `受験` 与 `受検` 不强行统一。

常用文案：

| 场景         | 文案                                 |
| ------------ | ------------------------------------ |
| 已确认       | 公式確認済み                         |
| 部分公布     | 一部発表済み                         |
| 尚未公布     | 公式発表待ち                         |
| 申请中       | 申込受付中                           |
| 已结束       | 受付終了                             |
| 信息核查中   | 公式情報確認中                       |
| 来源展开     | 公式ソースを確認                     |
| 确认日期     | 公式情報確認日                       |
| 无可发布事实 | 現在、公開できる公式情報はありません |

## 4. 设计令牌

### 4.1 颜色

颜色以语义为准。页面不得直接使用未登记色值。正文与背景须保持足够对比度；红色只表示真实错误、暂停、重要变更或订正，不用于普通强调和制造紧迫感。

| ------------------------ | --------- | -------------------- |
| `--color-ink`            | `#172033` | 正文、标题           |
| `--color-text-secondary` | `#334155` | 正文、二级标题       |
| `--color-muted`          | `#475569` | 辅助说明、确认时间   |
| `--color-primary`        | `#1D4ED8` | 品牌、链接、主要操作 |
| `--color-primary-hover`  | `#1E40AF` | hover、active        |

| `--color-bg`             | `#F6F8FB` | 页面背景             |
| `--color-bg-subtle`      | `#F8FAFC` | 次级内容背景         |
| `--color-surface`        | `#FFFFFF` | 卡片、表格、弹层     |
| `--color-border`         | `#DCE3ED` | 分隔线、卡片边框     |
| `--color-border-strong`  | `#CBD5E1` | 表格、控件、选中边界 |

| `--color-danger`         | `#B91C1C` | 变更、暂停、错误     |
| `--color-danger-bg`      | `#FEF2F2` | 高风险状态背景       |

色彩语义分为三个维度，不能压缩为一个通用状态：

1. **信息可信状态**：`verified / partially_announced / awaiting_official / previous_year_reference / under_review`。
2. **考试业务状态**：`application_open / application_closed / completed / suspended`。
3. **变化标记**：`changed_or_corrected`，可以与已确认、报名开放等状态同时存在，并使用独立通知展示。

同一区域最多并列显示一个可信状态和一个业务状态；变化标记以通知或独立标签表达。所有状态必须同时提供日文文字，不能只显示色点。

### 4.2 字体与排版

字体使用系统优先的日文无衬线字体栈：`system-ui`、`-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`Hiragino Sans`、`Hiragino Kaku Gothic ProN`、`Yu Gothic UI`、`Yu Gothic`、`Meiryo`、`sans-serif`。首发不加载大型外部日文字体，不混用装饰字体或衬线字体。

| 层级         | 桌面 | 移动端 | 行高 | 用途                   |
| ------------ | ---: | -----: | ---: | ---------------------- |
| 首页展示标题 | 44px |   34px | 1.25 | 仅首页首屏             |
| H1           | 36px |   30px |  1.3 | 页面主标题             |
| H2           | 28px |   24px |  1.4 | 页面模块               |
| H3           | 21px |   19px | 1.45 | 事实组、稳定子主题     |
| 卡片标题     | 18px |   18px |  1.5 | 卡片名称               |
| 强调正文     | 18px |   17px |  1.8 | 首屏说明、引导         |
| 正文         | 16px |   16px |  1.8 | 主要阅读内容           |
| 辅助         | 14px |   14px | 1.65 | 来源、状态补充         |
| 标签         | 13px |   13px |  1.5 | 状态徽章、表头         |
| 最小文字     | 12px |   12px |  1.5 | 非核心版权、技术元数据 |

标题和关键事实使用 `font-weight: 700`，控件和标签使用 `600`，正文使用 `400`。避免使用 `300` 或过粗的 `800/900`。数字、日期和统计表使用等宽数字特性；普通正文不增加夸张字间距。不要用小于 13px 的文字承载来源、状态、日期和操作。

解释型正文最大阅读宽度为 720px；连续日文正文每行约 32～42 个全角字符。正文不做两端强制对齐，不用图片文字替代可选择文字。

### 4.3 尺寸、间距与阴影

基础间距为 4px，允许值为 4、8、12、16、20、24、32、40、48、64、80px。页面模块间距桌面 64px、移动端 40px；卡片内边距桌面 24px、移动端 18～20px。

尺寸规则：

- 普通按钮和输入框高度为 44px，首屏搜索框和大按钮为 52px；移动端触摸目标不得小于 44×44px。
- 控件圆角 8px，普通卡片圆角 12px，首屏重点区域圆角 16px，状态标签使用全圆角。
- 普通卡片默认使用 1px 边框、无阴影；阴影只用于下拉菜单、抽屉、对话框和明确悬浮层。
- 卡片 Hover 不使用明显位移，不通过大阴影制造浮动效果。

### 4.4 图层与动效令牌

图层从低到高依次为：正文、页内吸顶导航、全局导航、下拉菜单、移动抽屉、对话框、Toast。广告不得高于全局导航，不得覆盖正文和控件。

动效时长使用 120～200ms；抽屉或对话框最多 240ms。只为状态变化、展开收起和操作反馈使用动效，不使用滚动视差、数字滚动、自动轮播、背景视频和弹跳动画。

## 5. 页面骨架与布局

公开页统一采用：

```text
顶部导航 → 页面标题/状态 → 关键事实 → 详细内容 → 官方来源 → 更新历史 → 页脚
```

布局使用 4/8/12 列响应式栅格：

| 视口          |         栅格 | 页面边距 | 列间距 |
| ------------- | -----------: | -------: | -----: |
| `< 768px`     | 4 列概念栅格 |     16px |   16px |
| `768～1023px` |         8 列 |     24px |   20px |
| `≥ 1024px`    |        12 列 |     32px |   24px |
| `≥ 1280px`    |        12 列 |     居中 |   24px |

全站最大容器宽度为 1200px；解释型正文最大宽度为 720px；日历、比较器和统计表可使用完整 1200px。详情页桌面布局建议为约 800px 主内容、320px 辅助栏和 32px 间距；移动端回归单列。

顶部导航必须包含品牌、主要入口和当前页面可识别的返回路径。页面首屏不放广告，不用广告打断关键日期和来源查看。普通详情页不使用满屏营销 Hero；首页首屏桌面高度建议控制在约 520～620px。

### 5.1 全局 Header

- 桌面高度 72px，移动端高度 56px。
- 桌面导航为：`資格を探す / 試験日程 / 比較する / データを見る / 更新情報 / 搜索`。
- 当前项同时使用主色文字和明确的选中形态，不能只靠轻微颜色差。
- Header 可以吸顶，但不得遮挡键盘焦点或锚点标题。
- 移动端显示品牌、搜索和菜单；完整导航进入抽屉。
- 不显示登录、会员、通知和消息中心入口。

### 5.2 移动端底部导航

- 固定项目：`探す / 日程 / 比較 / 更新`。
- 高度 64px，并为设备安全区预留空间。
- 当前项使用图标与文字共同强调。
- 不得与底部广告、Cookie 提示或页面操作条重叠。

### 5.3 面包屑与页内导航

- 除首页外，正式内容页必须提供面包屑。
- 使用用户可读名称，不显示 slug；最后一级不链接。
- 资格内导航为：`概要 / 日程 / 申込み・条件 / 試験内容 / 合格率`。
- 桌面页内导航可在 Header 下吸附；移动端允许水平滚动，当前项必须可见。
- 页内导航高度不超过 52px。

### 5.4 Footer

Footer 分为资格信息、数据工具、运营与方针、联系与纠错四组，并提供运营者信息、来源方针、编辑方针、AI 方针、广告方针、隐私、条款和纠错入口。不得放虚构认证、获奖、专家或用户口碑标识。

后台审核页可以使用更高信息密度，但仍沿用同一字体、颜色和状态语义；批准、拒绝、延期必须是清晰的按钮组，并在操作前要求审核理由。后台不使用公开站的营销首屏、移动底部导航、广告和内容推荐模块。

## 6. 核心组件

### 6.1 导航

桌面主导航：`資格を探す / 試験日程 / 比較する / データを見る / 更新情報`。移动端使用底部导航：`探す / 日程 / 比較 / 更新`。当前项使用主色和明确文字，不只依靠下划线或颜色变化。

### 6.2 状态徽章

状态徽章高度 24～28px，为短文本胶囊，使用浅色背景、深色文字和必要边框。状态必须紧邻对应资格或事实，不要把“公式確認済み”误用为“页面所有内容都已更新”。变更、暂停和核查中状态还应在模块边缘使用对应色的 4px 左边框。

可信状态、业务状态和变化标记分开表达。例如：`公式確認済み · 申込受付中`，并在存在订正时额外显示变化通知。资格卡片最多展示两个徽章，其余状态进入详情。

### 6.3 事实卡片

事实卡片包含：字段名、展示值、适用年度或维度、可信状态、官方确认日期和来源展开。日期、费用和合格率等关键值使用 20～28px 粗体；字段名使用辅助色。来源使用可展开控件，展开后显示官方机构、页面标题、官方 URL、覆盖字段、快照或版本标识和确认日期。

快速事实优先级为：报名截止、考试日、合格发表、费用、报考条件、考试方式。桌面通常 3～4 列，平板 2 列，手机按内容使用 1 列；不得为维持列数压缩文字。

### 6.4 目录卡片

目录卡片包含资格领域、正式名称、别名、信息状态和进入详情/报名条件的链接。卡片整体不应是不可访问的点击区域；链接必须有清晰的日文名称和可见焦点。

### 6.5 表格与比较

表格第一列为比较维度，表头在滚动时可保持可见；移动端允许横向滚动，但不得把长文本截断。缺失值显示“公式発表待ち”或“未確認”，不使用 `-` 掩盖数据状态。动态数字旁应能展开查看来源、适用年度和确认日期。

### 6.6 日期与日历事件

日期统一以日本标准时间（JST）解释，并显示明确日期格式，例如 `2026年10月18日`。事件颜色语义：报名开始为信息色、报名截止为警示色、考试日为主色、合格发表为成功色、变更/暂停为高风险色。倒计时只有在官方已确认精确日期时显示。

### 6.7 来源模块

来源模块使用白色卡片和清晰标题 `公式ソースと更新について`。至少显示来源名称、官方链接、覆盖范围、确认日期和状态说明。外部链接新窗口打开时应保留 `rel="noreferrer"`，并用文字说明会离开本站。

### 6.8 空状态与错误

空状态必须区分：官方待公布、本站正在确认、筛选无结果、API 暂时不可用、当前年度尚未达到发布条件。空状态解释“为什么没有内容”和“用户下一步可以做什么”，例如链接到官方来源或返回资格目录。不得用空白卡片制造已加载错觉。错误页面不泄露堆栈、数据库连接或内部路径。

### 6.9 操作控件

普通按钮高度 44px，大按钮 52px，触摸目标至少 44×44px。主操作使用主色实心按钮，次操作使用白底边框按钮，三级操作使用文本链接，危险操作使用危险色并要求确认。每个首屏或独立模块最多一个主按钮。

按钮文案使用“动词 + 对象”，例如 `日程を見る`、`比較に追加`、`カレンダーに追加`。禁止使用目的不明的“こちら”“詳しくはこちら”。官方外链使用独立的外链图标和明确文案，如 `公式サイトで確認`，不得与站内主按钮或广告混淆。

焦点态使用 2px 主色外框并与组件保留 2px 间距；Hover 不得是唯一反馈方式。输入框必须有可见 Label，不用 Placeholder 代替 Label。移动端表单字号保持 16px，避免浏览器自动缩放。

### 6.10 Button

Button 变体为 Primary、Secondary、Tertiary、Official External 和 Danger。必须定义 Default、Hover、Focus-visible、Active、Disabled 和 Loading。Loading 时保持按钮宽度，Disabled 时仍需保证文字可读，并在必要时说明不能操作的原因。

### 6.11 Input / Form

- 输入框、Select 和搜索框默认高度 44px；首页大搜索框 52px。
- Label 位于控件上方，帮助文字位于下方；错误文字紧邻对应字段。
- 错误状态同时显示边框、文字和必要图标，不只使用红色。
- Placeholder 只提供格式示例，不承担字段名称。
- Checkbox 和 Radio 的整个标签区域均可点击。
- 纠错表单只收集必要信息，提交成功或失败必须有明确反馈。

### 6.12 Search 与 Filter

搜索支持正式名称、简称和别名；建议项显示正式名称、类别和简称。无结果时提供清除条件和浏览目录入口。

桌面筛选器可以使用约 280px 左侧栏；移动端使用底部抽屉，底部固定 `適用する` 和 `クリア`。当前筛选以可移除 Chip 显示，筛选结果变化后保持滚动上下文并向辅助技术报告结果数量。

### 6.13 Tag / Badge / Chip

- Badge 只显示状态，不可点击。
- Tag 表达分类、年度或资格领域。
- Chip 表达可操作筛选条件，必须有 Hover、Focus、Selected 和移除状态。
- 分类色不得复用风险色，也不得为每个资格建立独立品牌色。

### 6.14 Icon

使用单一线性图标体系，默认 20px，紧凑场景 16px，重点场景 24px，描边约 1.75～2px。图标不能替代核心文字；搜索、关闭等通用图标也必须有可访问名称。禁止 Emoji 作为正式组件图标。

### 6.15 Dropdown

Dropdown 必须与触发控件对齐，最大高度受视口限制并允许内部滚动；支持键盘方向键、Esc 和焦点返回。选中项使用背景、勾选和文字共同表达。不得把关键页面导航仅放在 Hover Dropdown 中。

### 6.16 Modal 与移动抽屉

Modal 仅用于必须中断当前流程的确认、风险操作和复杂帮助，不用于普通来源查看或营销提示。打开后焦点进入弹层，关闭后返回触发元素，背景不可交互。移动端筛选优先使用底部抽屉；抽屉必须提供标题、关闭按钮和固定操作区。

### 6.17 Tooltip

Tooltip 只解释图标、术语或缩写，不承载关键日期、状态、错误和唯一操作。键盘 Focus 与指针 Hover 都能触发，内容简短并可被辅助技术读取。

### 6.18 Loading

公开内容优先服务端直接输出。只有异步工具使用骨架屏；骨架尺寸接近最终内容并避免布局跳动。持续等待时必须显示文字说明和重试入口。禁止无限旋转但不说明状态。

### 6.19 Alert 与 Toast

持久的重要状态使用页面内 Alert，短暂的操作结果使用 Toast。Alert 分为信息、待公布、变更/订正和错误四类。关键变化 Alert 不能永久关闭后无处再次查看；Toast 不用于高风险事实变化。

### 6.20 Accordion / Details

用于来源原文、状态说明、统计口径和较长 FAQ。禁止用 Accordion 隐藏关键日期、当前费用、报考条件和重要变化。来源条目可以同时展开，其他列表默认只展开必要项目。

### 6.21 Pagination

资格目录和更新中心优先普通分页；筛选条件在翻页后保留。不得把无限滚动作为唯一访问方式。分页控件满足 44px 触摸目标并标明当前页。

## 7. 响应式规则

| 视口          | 规则                                        |
| ------------- | ------------------------------------------- |
| `< 768px`     | 4 列概念栅格、16px 边距、底部导航、单列优先 |
| `768–1023px`  | 8 列、24px 边距、两列卡片、紧凑导航         |
| `1024–1279px` | 12 列、32px 边距、完整导航、主内容与侧栏    |
| `≥ 1280px`    | 1200px 居中容器，不继续无限拉宽             |

移动端优先保留：页面标题、当前状态、报名/考试日期、主要链接、来源展开和返回入口。次要说明可折叠，但不能折叠唯一事实值或状态解释。

组件转换规则：

| 模块       | 桌面            | 平板          | 手机                   |
| ---------- | --------------- | ------------- | ---------------------- |
| 顶部导航   | 完整横向        | 缩减间距      | 品牌、搜索、菜单       |
| 首屏       | 单栏或 7/5 双栏 | 单/双栏       | 单栏                   |
| 快速事实   | 3～4 列         | 2 列          | 1 列，短值可 2 列      |
| 资格卡     | 3 列            | 2 列          | 1 列                   |
| 详情页     | 主体 + 侧栏     | 主体 + 窄侧栏 | 单栏                   |
| 筛选       | 左侧栏/顶部栏   | 顶部/抽屉     | 底部抽屉               |
| 月历       | 完整月历        | 紧凑月历      | 默认时间线             |
| 比较       | 列式矩阵        | 可滚动矩阵    | 按维度纵向卡片         |
| 普通数据表 | 完整表格        | 受控滚动      | 卡片转换或表格内部滚动 |

页面本身不得产生横向滚动；仅比较矩阵和无法安全转换的数据表可以在独立容器内滚动。必须在 320px CSS 宽度下保持核心任务可用，并在 360px、768px、1024px、1280px 和 1440px 视口检查布局。

桌面侧栏内容进入手机端时按语义重新排列：状态和确认时间紧跟 H1；年度切换位于事实卡之前；相关工具位于正文后、来源前；广告至少在一个完整核心模块之后。禁止简单把整个侧栏移动到页面末尾。

## 8. 状态、异常与数据新鲜度

### 8.1 页面状态模型

页面最多同时表达三个维度：

1. 信息可信状态，例如 `公式確認済み`、`公式発表待ち`。
2. 考试业务状态，例如 `申込受付中`、`受付終了`。
3. 变化标记，例如 `変更・訂正あり`。

展示顺序为：重要变化通知 → 页面可信状态 → 页面业务状态 → 单项事实状态。不要在页面标题旁堆叠超过两个徽章。

### 8.2 新候选正在审核

如果已有旧的正式事实，继续显示最后一个已批准事实，并显示 `公式情報確認中`，注明旧事实的适用年度和确认时间；候选值不得提前展示。如果没有旧正式事实，不显示候选值，只显示核查状态与已确认的官方来源。

### 8.3 官方待公布

显示 `公式発表待ち` 和具体说明，不显示推测日期、往年日期替代、模糊月份或虚假倒计时。倒计时只能基于已批准的精确日期。

### 8.4 上一年度参考

上一年度信息必须位于独立灰色参考模块，明确显示年份和“当前年度尚未公布”。不得把上一年度值放进当前年度快速事实卡的主值位置。

### 8.5 已批准变更或订正

显示当前批准值，并提供 `変更前 → 変更後`、官方发布日期、本站反映时间和来源。红色只用于变化标签与实际影响，不把整个页面染红。变化在受影响页面和更新中心均可访问。

### 8.6 API 与来源故障

如果能够安全读取最后正式版本，继续显示该版本并标注最后确认时间及当前检查失败；如果无法安全读取正式事实，显示错误状态，不回退到 fixture、synthetic、测试数据或推断值。

### 8.7 三类时间

- `published_at`：本站页面首次发布。
- `updated_at`：页面可见内容最后发生真实变化。
- `official_verified_at`：最后成功检查官方来源。

页面不得把来源检查时间伪装成内容更新时间。用户侧建议分别写作 `ページ更新` 与 `公式情報確認`。

## 9. 页面模板

### 9.1 全局顺序

除首页外，页面基本顺序为：Header → 面包屑 → 页面标题/状态 → 页内导航或筛选 → 核心事实/任务 → 解释内容 → 来源与更新历史 → 相关页面 → 受控广告 → Footer。

### 9.2 首页

首页不是文章列表，模块顺序固定为：

1. 首屏定位、搜索、热门资格入口和年度日程主操作。
2. 即将发生的重要日期。
3. 首发资格卡片。
4. 跨资格工具。
5. 最新官方变化。
6. 数据来源与可信度说明。
7. 必要的受控广告与 Footer。

桌面首屏可以采用 7/5 双栏：左侧定位与搜索，右侧显示下一重要事件或可信度摘要；手机改为单列。首屏禁止大幅人物照片、课程截图、轮播、评论和广告。

### 9.3 资格目录页

顺序为：标题与说明 → 搜索 → 当前筛选和结果数量 → 筛选器与资格结果 → 分页 → 无结果状态 → 可信度说明。桌面使用约 280px 筛选侧栏和结果区域，平板与手机使用抽屉。卡片桌面 3 列、平板 2 列、手机 1 列。

### 9.4 资格综合页

顺序为：面包屑 → 资格名称、别名、可信状态与确认时间 → 当前年度切换 → 快速事实 → 资格内导航 → 资格简介 → 当前年度日程 → 报名条件 → 考试内容 → 合格率 → 最新变化 → 官方来源 → 更新历史 → 相关资格和工具。

首屏必须让用户在最少滚动下看到当前年度状态、报名或考试日期和来源入口。普通正文使用约 720px 阅读宽度；事实与工具可以使用更宽区域。

### 9.5 年度考试页

顺序为：年度 H1 → 年度可信状态和业务状态 → 重要变化通知 → 全年时间线 → 事件详情 → ICS 操作 → 灾害、延期、订正 → 官方资料 → 来源与历史。

时间线节点显示事件类型、日期与星期、业务状态、简要说明、来源和 ICS。当前或最近事件突出，过去事件降低视觉权重但保持完整可读。

### 9.6 报名与条件页

顺序为：当前报名状态 → 报考条件 → 申请方式 → 申请步骤 → 材料清单 → 费用与支付 → 常见遗漏 → 官方报名入口 → 与上年度的变化 → 来源。

使用步骤、检查清单和表格，不把流程写成连续长文。官方报名入口使用明确外链样式，附近禁止广告。

### 9.7 考试内容页

顺序为：考试概览 → 科目与题量 → 考试时长与形式 → 评分与合格标准 → 免除规则 → 官方大纲与样题 → 制度变更 → 来源。禁止生成无官方依据的难度评分。

### 9.8 合格率与统计页

顺序为：最新年度指标 → 统计口径 → 历年趋势图 → 年度数据表 → 解读边界 → 逐年来源。必须说明历史合格率不等于个人通过概率。

### 9.9 日历工具页

提供月历、时间线和表格三种视图。桌面可以默认月历或时间线，手机默认时间线。筛选包括资格、事件类型和年份。所有事件都能查看来源、确认时间、资格年度页及 ICS 操作。

### 9.10 比较工具页

允许选择 2～3 个资格。顺序为：选择对象 → 关键事实差异摘要 → 完整维度比较 → 动态事实来源 → 相关比较指南。摘要只陈述事实，不给出“更值得考”“更容易”等绝对结论。

### 9.11 更新中心与更新详情

更新中心是事实变化日志，不是普通新闻栏目。更新详情展示变化类型、日期、受影响资格、影响字段、旧值与新值、实际影响、官方原文摘要、来源、本站反映时间和相关页面。

### 9.12 指南与可信度页面

指南、来源方针、编辑方针、AI 方针、广告方针、隐私、条款和纠错页面使用约 720px 正文宽度；长文可在桌面提供约 240px 页面目录。政策页禁止广告和营销 CTA。

### 9.13 错误与空页面

错误页必须说明发生了什么、哪些数据没有显示、用户可以如何继续。404 提供资格目录、日程和搜索入口。不得显示内部路径、堆栈、数据库或服务细节。

## 10. 图标、图像与数据可视化

### 10.1 图标

状态图标固定语义：已确认为圆形勾选，待公布为时钟，核查中为放大镜或更新，变化为警示，来源为文档/外链，日期为日历，ICS 为日历加号。不得在不同页面为相同状态更换图标。

### 10.2 图像与插画

首发不依赖照片和插画建立页面层级。允许使用功能图表、时间线、流程示意和必要截图；禁止通用备考人物图库、虚构专家头像、AI 生成用户证言、吉祥物主导页面及未经许可的实施机构标志。

### 10.3 图表

- 图表必须有标题、时间范围、统计口径、来源和文字摘要或数据表。
- 折线图用于趋势，条形图用于比较；禁止 3D 图表、速度表和把合格率做成个人概率仪表盘。
- 多系列图表可以使用蓝、青绿、紫、橙、洋红和灰等可区分序列，但不得把图表系列色作为资格全站品牌色。
- 不能只通过红绿颜色区分系列；使用线型、标记、标签或直接注释补充。
- 数字右对齐并使用等宽数字；百分比显示明确分母与小数规则。

## 11. 动效与交互反馈

- 普通 Hover、Focus 和展开使用 120～200ms；抽屉与对话框不超过 240ms。
- 禁止自动轮播、滚动视差、自动播放背景媒体、持续数字跳动和纯装饰动画。
- 支持 `prefers-reduced-motion`，关闭非必要位移与渐变动画。
- 所有交互组件必须定义 Default、Hover、Focus-visible、Active、Selected、Disabled、Loading，表单另有 Error。
- Hover 不得是唯一反馈；触屏和键盘必须获得等价状态。
- 操作成功或失败必须在触发位置附近或通过可感知状态消息反馈。

## 12. 可访问性与内容质量

- 目标为 WCAG 2.2 AA：正文与背景至少 4.5:1，大号文字至少 3:1，非文本控件边界和状态满足必要对比度。
- 所有页面使用正确的 `lang="ja"`、唯一 H1 和按层级递进的标题。
- 链接文本描述目的，图片若存在必须有替代文本；信息图不能成为唯一信息载体。
- 键盘可以到达导航、筛选、来源展开、表格和操作按钮；焦点不可被裁切或隐藏。
- 不依赖颜色、动画或悬停显示信息；尊重 `prefers-reduced-motion`。
- 日期、费用、合格率必须同时显示单位、统计口径、适用年度和数据状态。
- 事实内容与解释内容分开，解释不得新增未批准的数字或制度事实。
- 普通交互目标最小 44×44px；紧凑桌面工具栏可以使用 36～40px 视觉高度，但可点击区域仍应满足要求。
- 页面在 200% 文字放大和 320px CSS 宽度下仍能完成核心任务。
- 表格使用正确表头与 Caption；图表提供数据表或文字摘要。
- 筛选结果、表单错误、Loading 完成和 Toast 等状态变化应被辅助技术感知。
- 正文链接默认具有可辨识链接样式；仅导航和按钮型链接可以不显示永久下划线。

## 13. 广告与商业化边界

- 广告必须明确标记 `広告`，不得伪装成事实卡、官方下载、官方报名入口或站内导航。
- 首屏搜索、快速事实、日期倒计时、官方链接、ICS 操作、比较选择区、筛选器和纠错提交区禁止放广告。
- 广告与官方链接、关键日期和操作控件之间至少保留 24px 视觉距离。
- 广告容器预留尺寸，避免布局跳动；广告加载失败不得阻塞主要内容。
- 首页建议 0～2 个广告位，资格与内容详情页 1～3 个，年度页 1～2 个，日历/比较器 0～1 个，政策与纠错页 0 个。
- 移动端禁止覆盖式、全屏式和与底部导航冲突的吸底广告。
- 不为增加广告展示拆分页、制造无价值分页或打断完整步骤。

## 14. 禁止的设计方式

以下规则已经确认，后续不得自行引入：

- 大面积高饱和渐变、玻璃拟态、霓虹色、3D 拟物和厚重阴影。
- 满屏营销 Hero、自动轮播、背景视频、滚动视差和持续动画。
- 卡通吉祥物、通用备考人物图库、虚构专家头像和虚构用户评价。
- 每个资格使用一套独立品牌色，或用风险色表达资格类别。
- Emoji 作为正式图标，或仅使用图标不提供核心文字。
- 用红色表达普通强调、倒计时焦虑、推荐或“更值得考”。
- 难度星级、主观推荐分、年收入排名、“必过”“最简单”等表达。
- 把所有正文模块都包装成浮动卡片，或使用大圆角制造娱乐化观感。
- 用 Placeholder 替代 Label，用 Tooltip 隐藏关键事实，用 Accordion 隐藏唯一的日期、费用或条件。
- 用 `0`、空白或单独的 `-` 混淆未公布、未确认、不适用和加载失败。
- 官方待公布时显示推测日期、往年日期替代、模糊预计月份或倒计时。
- 把测试、fixture、synthetic 或待审核候选值展示为公开事实。
- 视觉上暗示本站为日本政府、考试实施机构或官方报名系统。

## 15. 公开页面验收清单

每个公开页面上线前至少确认：

1. 首屏能看到页面目的、资格名称和当前信息状态。
2. 动态事实都有适用年度、确认日期和官方来源入口。
3. 未确认的日期、费用和制度信息没有被猜测或伪造。
4. 移动端无横向页面溢出；表格若较宽则在表格容器内滚动。
5. 键盘焦点、标题层级、链接名称和颜色对比可用。
6. 空状态、接口错误和官方发表待机状态均有清晰说明。
7. 页面不会把历史年度信息误显示为当前年度信息。

同时检查：

8. 只使用已登记的颜色、字号、间距、圆角和状态文案。
9. 页面本身在 320px 宽度无横向溢出；宽表只在独立容器内滚动。
10. Header、页内导航、底部导航和 Cookie/广告层不遮挡焦点和内容。
11. Button、Input、Dropdown、Modal、Tooltip、Accordion 均具有完整交互状态。
12. 关键事实不因卡片列数、文本截断或折叠而丢失。
13. 图表有口径、来源和数据替代；表格数值与单位格式统一。
14. 广告位置符合安全距离且不造成误触或 CLS。
15. 日文术语与实施机构一致，不存在保证、排名和虚构体验。

建议使用以下视口进行视觉验收：360、768、1024、1280、1440px。内容压力测试至少覆盖长资格名称、长来源标题、多个状态、未公布值、上一年度参考、三项资格比较和大量日历事件。

## 16. 审核后台边界

审核后台共享颜色、字体、状态、按钮、表单和可访问性令牌，但采用更高信息密度：桌面优先、可使用约 14px 表格正文和 44px 行高，最大内容宽度可以扩展至 1440px。

后台固定要求：

- 侧栏或明确导航展示审核队列、来源、候选事实和历史。
- 候选值、当前正式值、官方原文证据、来源 URL 和快照标识可并列核对。
- 高风险字段和冲突使用清晰警示，不依赖背景色。
- Approve、Reject、Defer 具有明确差异，均要求审核理由；危险操作提供确认。
- 不使用广告、公开站推荐模块、营销 Hero 和移动底部导航。
- 手机端可以支持查看，但高风险审核操作应优先在足够宽的屏幕完成。

## 17. 实现约束与改造顺序

现有公开页使用服务端渲染和内联 CSS；后续拆分组件或引入样式文件时，必须保持本规范中的令牌、状态文案和来源展示规则。UI 变更不得修改事实审核链、数据来源权限或动态事实口径；若视觉需求与官方事实状态冲突，以事实状态和可追溯性为准。

后续 Codex 实施 UI 升级时应按以下顺序：

1. 完整读取本文件、`docs/product-design.md` 和相关数据契约。
2. 盘点现有页面、状态与测试，保留业务行为和用户已有改动。
3. 建立集中设计令牌、基础排版和全局页面容器。
4. 统一 Header、Footer、面包屑、页内导航和移动底部导航。
5. 建立 Button、Input、Badge、Alert、Empty/Error/Loading 等基础组件。
6. 建立事实卡、来源展开、时间线、表格、筛选器、比较和图表模式。
7. 按资格目录 → 资格详情及子页 → 首页 → 年度页 → 工具页的顺序迁移。
8. 最后处理广告安全区、性能、可访问性和视觉回归。

实现边界：

- 不允许每个页面复制独立的完整样式体系。
- 页面不得直接写死动态日期、费用、状态和来源。
- 不因视觉迁移改变 URL、公开 API 契约、审核规则和事实过滤。
- 重构时保持渐进可验证；每完成一类组件即运行相应测试并检查移动端。
- 若现有实现与本规范冲突，先报告冲突和迁移影响，再按本规范调整；不得静默改变业务含义。

## 18. 已确认规则与尚未确定事项

### 18.1 已确认规则

- 定位为可信数据媒体与轻量资格考试工具，不做课程营销站。
- 使用浅色主题、可信蓝主色、系统日文字体、1200px 最大容器和 720px 阅读宽度。
- 使用 4/8/12 列响应式栅格、44px 触摸目标、12px 卡片圆角和边框优先的卡片风格。
- 信息可信状态、考试业务状态和变化标记分开表达。
- 手机端使用 `探す / 日程 / 比較 / 更新` 底部导航，日历默认时间线。
- 关键事实就地展示适用年度、状态、确认时间和来源入口。
- 不引入外部 Web Font、深色主题、人物图库、虚构证言、吉祥物和强营销动效。
- 目标为 WCAG 2.2 AA，广告不得干扰核心任务。

### 18.2 尚未确定事项

以下事项没有在本轮设计讨论中最终确定，后续不得自行假定：

- 正式产品名称、域名品牌文字和最终 Logo 图形。
- 具体图标库或自绘图标资产，只确认了线性图标风格与尺寸。
- 具体图表实现库，只确认了图表视觉、语义和可访问性规则。
- 最终广告供应商、具体广告尺寸和商业投放策略。
- 是否在首发后增加自托管日文字体、深色模式或独立插画体系。

这些事项不影响按本规范进行公开页面基础升级；如需决定，应单独提出并获得确认。
