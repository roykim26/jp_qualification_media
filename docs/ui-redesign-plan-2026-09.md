# 公开网站 UI 改造规划

> 2026-09-22。依据 `product-design.md`、`design-system.md` 与当前 `apps/web` 实现。范围为公开网站；审核后台沿用原有高密度工作台规范。

## 目标与边界

网站要让考生在首屏完成三件事：找到资格、确认信息状态、进入日程或官方来源。视觉定位仍是“可信数据媒体 × 轻量工具”：浅色、可信蓝、系统日文字体、克制的分隔线和卡片。动态日期、费用、合格率、状态与来源只读已批准数据；界面不填补空缺。

## 现状诊断

| 页面/区域      | 当前问题                                                                     | 改造方向                                                                             |
| -------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 全局导航       | 品牌仅为一行长文字；未开放入口和禁用搜索占据主导航                           | 品牌形成清晰识别区；导航只展示可用任务；搜索直达资格目录                             |
| 首页           | 首屏没有可输入搜索；右侧可信说明与下方可信模块重复；“重要日程”实际是静态引导 | 搜索成为首要操作；右侧以三步事实核验说明承载信任；日程模块明确为入口，不伪装实时预告 |
| 资格目录       | 六张卡片信息层级平均、子页链接过多；搜索与结果概况分离                       | 搜索、结果、状态串成一条任务路径；卡片先给名称与状态，子链接成为次级操作             |
| 资格详情       | 标题区与侧栏重复状态；移动端把整块侧栏置于事实前                             | 首屏状态和确认时间保留；侧栏拆分为年度与相关入口，窄屏在事实后出现相关入口           |
| 日程/比较/更新 | 工具页缺少明显任务引导；长值和横向比较易造成阅读负担                         | 统一页面标题、筛选区、结果计数、内容行与来源的层级；比较表保持容器内滚动             |

## 页面体系与优先级

1. **基础层**：保留现有设计令牌，强化页面背景、导航当前态、输入焦点、卡片标题与辅助信息。维持 1200px 容器、720px 正文、44px 最小触摸目标。
2. **全局框架**：品牌、桌面导航、移动菜单、底部导航、页脚。未实现功能不出现在主操作区；搜索跳转已存在的 `/shikaku/`。
3. **首页**：首屏按“定位 → 搜索 → 日程”排列，热门资格是快捷入口；下方按日程入口、六资格、工具、可信度排列。官方更新仅在有真实变更数据时可做动态列表，当前不生成假内容。
4. **目录与详情**：统一状态徽章、年度、官方确认时间、事实值和来源链接的顺序。卡片与事实模块使用一致边框和留白。
5. **工具页**：日程筛选与事件时间线、比较选择与表格、更新前后值。空状态明确说明“暂无已批准事实”，并提供可用返回路径。
6. **验证**：桌面与 360px 手机至少覆盖首页、目录、详情、日程、比较；检查键盘焦点、溢出、长日文、空状态和来源。运行类型检查及相关渲染测试。

## 验收标准

- 320px 页面无水平溢出；宽比较矩阵只在自身容器滚动。
- 页面标题、当前状态、主操作在首屏清晰；禁用入口不混入可点击导航。
- 动态事实保持年度、确认时间、来源；待公布状态不显示推测值。
- 搜索、筛选、ICS、比较和资格内导航继续沿用现有 URL 与行为。
- 不引入未登记颜色、外部字体、宣传照片、主观排名或虚构更新。
