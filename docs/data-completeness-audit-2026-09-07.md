# 数据完整性排查报告（2026-09-07）

## 1. 结论

当前项目已经具备六个首发资格的页面骨架、统一事实链、公开 API、比较、日历、更新页和技术 SEO 基线，但尚未达到产品规划中的“六个资格关键事实完整”和“关键事实官方来源覆盖率 100%”。

当前本地数据库共有 101 条已批准正式事实。这些数据足以验证数据链和页面能够运行，但不能证明业务字段完整。现有发布门禁主要按每个资格的事实条数验收，没有验证必需字段、适用维度、年份、新鲜度和页面实际内容，因此“门禁通过”与“数据完整”不是同一概念。

本报告以以下内容为基准：

- `docs/product-design.md` 中的完整产品数据要求；
- `docs/stage-log.md` 截至 2026-09-07 的最新阶段记录；
- `docs/data-contract.md`、`docs/api-contract.md` 和各资格来源契约；
- 当前解析器、公开页面字段映射和发布门禁；
- 2026-09-07 本地 PostgreSQL 数据及 `var/official-snapshots` 中的本地快照。

本次没有重新访问官方站点，因此本报告判断的是“项目内是否已经具备所需数据”，不代表对 2026-09-07 各官网最新内容完成了重新核验。

1. 资格性质；
2. 实施机构；
3. 报考条件；
4. 费用；
5. 考试频率；
6. 考试方式；
7. 科目数量；
8. 考试时间；
9. 历年合格率；
10. 下一次报名截止；

当前比较器实现的是报名截止、考试日程、考试方式、考试时间、费用、报考资格、合格标准和合格率 8 行。它缺少资格性质、实施机构、考试频率和科目数量，同时加入了规划中不是主要比较维度的合格标准。

## 6. 门禁与展示问题

### 6.1 发布门禁只检查数量

`config/release-gate-baseline.json` 当前只规定每个资格应有 6、6、2、10、38、39 条正式事实。`scripts/verify-lib.mjs` 检查事实数量、API 是否为 `verified`、页面能否打开和是否包含资格名称，但不检查：

- 必需字段是否全部存在；
- 机构、等级、科目、方式组合是否完整；
- 是否覆盖当前年度；
- 来源是否刚刚检查；
- 页面分区是否真正存在可展示事实；
- 比较器要求的维度是否可用；
- 合格率页是否有统计数据。

这会导致 FP 有 39 条、簿记有 38 条仍能通过门禁，但整类报名、资格、结果或合格率数据为空。

### 6.2 状态过于粗糙

当前 `services/api/src/public-view.ts` 以 `facts.length > 0` 判断整个资格为 `verified`。比较表单元格缺失时统一显示“公式未确认”。因此以下原因被混为一谈：

- 官网尚未公布；
- 项目尚未采集；
- 解析器没有覆盖；
- 候选仍在审核；
- 字段不适用于该资格；
- 数据存在但字段映射无法消费。

## 7. 整改优先级

### P0：上线前必须处理

1. 建立正式的“资格 × 年度 × 字段 × 机构/等级/科目/方式”覆盖清单。
2. 把发布门禁从事实数量改为必需维度完整性、新鲜度、来源和审核链检查。
3. 区分“尚未公布”“尚未采集”“审核中”“不适用”“映射异常”等状态。
4. 修复基本信息技术者字段命名与页面、比较器映射不兼容的问题。
5. 补齐宅建、行政书士、IT Passport 和基本信息技术者的稳定考试规格。
6. 补齐 FP 的年度日程、报考资格和未覆盖机构/级别组合。
7. 防止 CI 固定时间的快照和核验时间被当成正式环境的新鲜数据。

### P1：形成完整数据产品

1. 为六资格导入多年报名人数、受考人数、合格人数、合格率和统计口径。
2. 建立机构关系、等级、考试事件、费用、报考资格、考试规格和年度统计领域表。
3. 补齐来源元数据、快照元数据、采集运行、字段校验和异常记录。
4. 将动态比较器扩展到产品规划中的完整 11 个维度。
5. 建立真实事实变更历史、页面发布时间/更新时间和事实影响索引。

## 8. 验收原则

后续不能再使用“事实总数达到基线”作为数据完整性的唯一标准。每个资格至少需要同时满足：

1. 资格适用的 P0 字段均有明确状态；
2. 已公布字段均绑定官方来源、真实快照和审核/批准记录；
3. 尚未公布、尚未采集、审核中和不适用可以被区分；
4. 多级别、多机构、多科目和多方式数据没有被错误合并；
5. 页面、比较器、日历和 API 对同一事实的消费一致；
6. 当前年度事实具有真实来源检查时间；
7. 合格率页只有在统计人数、口径和来源完整时才视为完成；
8. CI fixture 只用于回归测试，不作为生产数据完整度和新鲜度证明。
