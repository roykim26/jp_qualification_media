## 🔴 高：优先整改

### H1. 「官方」名义易被误认为考试机构官网（景品表示法·误认诱导 / 商标·混同）

**现状（实测）**

- 站点名、`<title>`、页眉品牌均为「資格試験の公式情報」，副标题「公式発表を、探しやすく。」。
- 事实徽章为「公式確認済み」。
- 全站**没有任何**「本サイトは各試験実施機関の公式サイトではありません／非公式の個人運営サイトです」的明确声明（代码 grep 无「非公式」「公式ではありません」等表述）。
- 运营者页仅说「独立して運営」，利用规约仅说「参考情報」，均未直接否认官方身份。

**风险**：个人运营的聚合站以「公式」作为自己的站名，普通用户易误以为是 RETIO／IPA／経産省等实施机构的官网或获其背书；既可能构成景表法上的误认诱导，也可能引发实施机构的混同/投诉。这是当前最容易被指摘、且修复成本最低的一项。

**整改方案**

1. 全站显著位置（页脚＋首页＋运营者页）加一句免责声明：「本サイトは個人が運営する非公式の参考情報サイトであり、各試験実施機関の公式サイトではありません。掲載内容は公式発表を出典として整理したものです。」
2. 评估把站名中的「公式」去掉或改为描述性副标题（如品牌「資格試験情報ナビ」＋副标题「公式発表を、探しやすく。」），避免「公式」成为站点自身名称。
3. 将徽章「公式確認済み」的语义在页面上注明为「公式発表と照合・確認済み」（已核对官方发布），而非「官方认证/背书」。

### H2. 10 条已批准事实显示不准确/不完整（正确性·景表法·信任）

**现状（本地库只读核对，facts 共 1007 条 approved，其中 10 条显示值异常）**

| 资格   | fact_key                                      | 显示值问题                                                  |
| ------ | --------------------------------------------- | ----------------------------------------------------------- |
| takken | result_date                                   | `令和8年11月25日(水)9` —— **截断**，缺「時/分」，信息不完整 |
| takken | exam_date                                     | `2026-10-18T13:00:00+09:00` 原始 ISO，未格式化              |
| fp     | application_deadline ×2 / application_open ×2 | 原始 ISO 逗号串，未格式化（4 条）                           |

**风险**：截断的日期、无单位的费用/时长属于不准确/易误导展示，与站点「准确、不推测」的承诺相悖；raw ISO/英文枚举降低可读性与可信度。

**整改方案**

1. 修复 capture/parse 导致 `result_date` 截断的根因（display_value 在采集/解析环节被截断），重抓并走审批回写。
2. 增加显示格式化层：费用→「8,200円」、时长→「120分」、题数→「50問」、枚举→日文标签（paper→「紙筆（マークシート）」等）、ISO→「2026年10月18日(日) 13:00」。
3. 加回归门禁：display_value 不得以孤立数字结尾、不得为纯 ISO/纯枚举/无单位裸数字，防止再犯。

## 🟠 中：个人信息与启用前必修

### M1. 个人信息/运营者联系渠道仅有公开 GitHub Issues（個人情報保護法）

**现状**：お問い合わせ／訂正／開示請求全部指向公开 GitHub Issue；无邮箱或私密表单。运营者姓名/地址/联系方式「请求后开示」。

**风险**：个人信息的开示·订正·删除请求（APPI）走公开 Issue 无法私密核验身份，且可能诱导用户公开个人数据；「请求后开示」也缺乏私密受理渠道。

**整改方案**：为个人信息与运营者请求增加私密渠道（专用邮箱或表单），GitHub 仅保留公开订正；在隐私政策中写明个人信息咨询窗口。

### M2. 若启用 GA4/AdSense，需先补 Cookie·外部送信合规（電気通信事業法 2023 改正）

**现状（实测）**：当前 GA/广告/联盟**均未启用**（首页无 gtag/adsbygoogle，`GA_MEASUREMENT_ID` 为空）——这是好的。但隐私政策已预写「GA4/第三者广告を利用する場合」，且无 Cookie 同意/外部送信告知/_opt-out_ 机制。

**风险**：一旦启用基于 Cookie 的 GA4/AdSense，向 Google 外部送信用户信息需依电信事业法履行告知/同意或提供 opt-out；目前无此机制。

**整改方案（启用前必修，当前可暂缓）**：启用前先加 Cookie 同意横幅＋外部送信告知＋opt-out 链接，并把隐私政策从「する場合」更新为实际状态；完成后再开启 `GA_MEASUREMENT_ID`/广告。

## 🟡 低：安全加固 / 可选

### L1. 缺少安全响应头

**现状（实测）**：无 `Strict-Transport-Security`、`X-Content-Type-Options`、`X-Frame-Options`、`Content-Security-Policy`、`Referrer-Policy`、`Permissions-Policy`。HTTPS/跳转/证书本身正常。

**整改方案**：在 `deploy/Caddyfile` 的 `shikakucheck.com` 块加 `header` 指令：HSTS（`max-age=31536000; includeSubDomains`）、`X-Content-Type-Options nosniff`、`X-Frame-Options DENY`、`Referrer-Policy strict-origin-when-cross-origin`、基础 CSP。属加固项，非法律强制。

### L2. 运营者信息最小化（可选）

**现状**：姓名/地址/联系方式仅「请求后开示」。非商业信息站不触发特商法，可接受。

**整改方案**：若未来靠广告/联盟变现，建议补充更清晰的运营者披露；当前可维持。

## 整改优先级建议

1. **H1**（加非官方免责声明＋评估站名）——成本最低、风险最高，先做。
2. **H2**（修截断＋显示格式化＋门禁）——直接影响准确性承诺。
3. **M1**（私密联系渠道）——APPI 合规。
4. **L1**（安全响应头）——顺手加固。
5. **M2**（Cookie/外部送信）——仅在启用 GA/广告前做。
