# 公开网站 UI 详细迭代设计方案

> 版本：1.0 · 2026-09-22  
> 适用范围：`apps/web` 公开页面。本文是后续逐页改造的设计与验收标准，本轮只交付文档。  
> 上位依据：`product-design.md` 定义产品与事实边界，`design-system.md` 定义令牌和基础组件，`ui-redesign-plan-2026-09.md` 定义问题与改造方向。发生冲突时依上述顺序处理；本文负责将既定原则细化到页面。

## 1. 改造目标与判定方法

网站面对的核心任务是：**找资格、核实当前年度事实、安排日程、比较差异、追溯官方变化**。每个公开页面须让用户快速理解“这里有什么、信息适用哪一年、是否已获官方确认、下一步去哪”。视觉表达服务于查证效率，不以点击量或广告为优先。

后续实施应同时满足四个结果：

1. **任务明确**：页面首屏有唯一 H1、简短用途说明和一个主要任务入口。
2. **事实可查**：动态值就近显示适用年度、维度、状态、官方确认时间和来源入口；页面级“已确认”不能代替单项事实证据。
3. **状态诚实**：待公布、正在核查、上一年度参考、数据不可用分别展示，不用空白、`-`、推测日期或往年值冒充当年值。
4. **跨设备一致**：320px 到 1440px 可完成同一核心任务；响应式改变排列和信息密度，不删去关键事实与来源。

本方案的线框为结构说明，不指定未确认的正式品牌名、Logo、图标库、图表库或广告供应商。所有日文示例是界面文案示意；涉及实际年度、日期、费用、人数和来源时必须从已批准数据生成。

## 2. 当前基线与交付分层

| 类型         | 已有能力或页面                                                                                                  | 本方案要求                                                                               |
| ------------ | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 可直接改造   | 首页 `/`、目录 `/shikaku/`、资格综合与四类子页、`/schedule/`、`/compare/`、`/updates/`、指南与比较指南、404/502 | 调整结构、组件、响应式、状态表达；保留现有路由、搜索、ICS、筛选与事实规则                |
| 有条件显示   | 首页近期事件、首页最新更新、详情快速事实摘要、年度变化通知                                                      | 仅在已批准 API 提供所需数据及来源时显示；不足时用明确入口或空状态，不填示意事实          |
| 后续功能设计 | 月历/表格视图、事件类型筛选、目录多维筛选、统计专题、独立更新详情、政策/纠错页                                  | 本文定义最终 UI 形态；实现时先建立对应数据、路由和交互契约，不能把视觉占位当成已上线功能 |

当前首页已具备搜索与入口卡片，但尚非动态近期事件面板；当前日程是列表，比较页是横向矩阵；目录当前支持名称搜索，其他筛选未接入。后续任务应按上表判断功能成熟度，公开导航只出现可用页面。

## 3. 全局视觉与布局规则

### 3.1 画布、栅格和文字

沿用 `design-system.md` 的浅色令牌：正文 `#172033`、主色 `#1D4ED8`、背景 `#F6F8FB`、白色内容面、边框 `#DCE3ED`。不新增页面专用品牌色。普通卡片 12px 圆角、1px 边框、默认无阴影；首屏重点容器可用 16px 圆角。阴影只给真正浮起的菜单、抽屉、对话框。

| 视口        | 容器与排布               | 页面间距                    | 主要变化                             |
| ----------- | ------------------------ | --------------------------- | ------------------------------------ |
| 320–767px   | 左右 16px；单列优先      | 模块间 40px、卡片内 18–20px | 56px 顶栏、64px 底栏、筛选入口易触达 |
| 768–1023px  | 左右 24px；8 列概念栅格  | 模块间 48px、列距 20px      | 双列卡片，复杂侧栏降级为顶部区       |
| 1024–1279px | 左右 32px；12 列概念栅格 | 模块间 64px、列距 24px      | 完整顶栏、详情双栏                   |
| ≥1280px     | 最大 1200px 居中         | 模块间 64px                 | 内容不继续拉宽；正文最大 720px       |

首页展示 H1 桌面 44px、手机 34px；其他 H1 桌面 36px、手机 30px；H2 桌面 28px、手机 24px。正文 16px、行高约 1.8。来源与状态补充至少 13px。数字和日期启用等宽数字。连续解释文字控制在 720px 内，宽表、比较器和日历可使用完整容器。文字放大到 200% 后不得丢失操作。

### 3.2 全站信息层级

页面从上到下采用：**位置 → 结论/状态 → 核心事实或任务 → 解释 → 来源与历史 → 相关入口**。资格页面的主标题旁最多放一个可信状态和一个业务状态；已批准变化使用独立通知。状态不可仅靠颜色表达，必须有日文名称。页面更新与官方核查时间分别命名为 `ページ更新`、`公式情報確認`。

文字与按钮层级：每个首屏最多一个主色实心按钮；次操作为边框按钮；来源和相关页面为明确文本链接。所有表单有常显 Label，Placeholder 只给示例。外部官方链接使用 `公式サイトで確認` 一类明确文案并标识新窗口。

### 3.3 全局框架

| 区域       | 桌面                                                         | 手机                       | 验收重点                                         |
| ---------- | ------------------------------------------------------------ | -------------------------- | ------------------------------------------------ |
| Header     | 72px；文字品牌、可用主导航和搜索入口                         | 56px；品牌、搜索、菜单     | 当前项有文字与背景选中态；禁用功能不混入导航     |
| 面包屑     | 内容页位于标题之前                                           | 可换行，最后项为当前页     | 使用日文名称，不显示 slug；首页不需要            |
| 资格内导航 | 顶栏下吸附，五项：概要、日程、申込み・条件、試験内容、合格率 | 可横向滚动且当前项可见     | 锚点/键盘焦点不被吸顶层遮挡                      |
| Footer     | 资格、工具、运营方针、纠错联系四组                           | 分组纵排                   | 未上线链接不伪装可点击；运营者与方针页上线后补齐 |
| 底部导航   | 不显示                                                       | 固定探す、日程、比較、更新 | 有安全区、当前态；不遮挡内容或广告               |

正式产品名尚未确定，当前文字品牌仅为可替换占位；不得把它升级成暗示政府认证的徽章。首页、目录和工具页的导航状态按实际任务归属设置；指南归属应在正式导航扩展时统一确定。

## 4. 核心组件规格

| 组件      | 内容及顺序                                              | 状态与操作                                       | 尺寸与移动规则                                         |
| --------- | ------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------ |
| 状态徽章  | 图标（可选）＋日文状态文字                              | 可信、业务、变化三个维度分离                     | 24–28px 高；13px 字；手机不缩写为色点                  |
| 资格卡    | 分野/类别 → 正式名称 → 别名 → 状态 → 下一步链接         | 整卡不做单一隐形点击区；名称和操作可聚焦         | 桌面 3 列、平板 2 列、手机 1 列；长名称换行            |
| 事实卡    | 字段名 → 主值 → 维度/年度 → 可信状态与确认日 → 来源展开 | 缺失时显示原因，不渲染伪主值；来源能用键盘展开   | 主值 20–28px；详情桌面 2–4 列按内容，手机 1 列         |
| 事件节点  | 日期/星期 → 类型 → 资格与事件说明 → 来源/确认日 → ICS   | 仅有已批准精确日期才显示 ICS 与倒计时            | 桌面左右分区，手机单列；历史事件可弱化边框但文字仍清晰 |
| 变化卡    | 变化类型/时间 → 资格/字段 → 旧值与新值 → 来源/影响页    | 无旧值的首次发布显示“公開値”，不伪造“変更前”     | 手机旧值、新值上下排列                                 |
| 比较单元  | 值 → 适用年度/维度 → 来源/确认日                        | 缺失原因使用完整文字；不空表格单元               | 宽矩阵只在自身容器内滚动；后续可加手机逐维卡片         |
| 空/错状态 | 明确标题 → 原因 → 下一步                                | 待公布、核查中、筛选无结果、API 故障分别使用文案 | 紧贴受影响模块；不得覆盖其他已确认事实                 |

按钮最小 44×44px，首屏搜索输入与主按钮 52px 高。Default、Hover、Focus-visible、Active、Disabled、Loading 均需定义；表单另有 Error。焦点为 2px 可见描边并留偏移。筛选 Chip 与状态 Badge 在视觉和交互上不可混同：前者可移除，后者只读。

### 4.1 缺失和异常的文案矩阵

| 情况                       | 主显示                         | 辅助说明/动作                                          |
| -------------------------- | ------------------------------ | ------------------------------------------------------ |
| 官方尚未公布               | `公式発表待ち`                 | 说明当前年度尚无官方发布日期；给官方来源或资格概览入口 |
| 本站已发现候选但仍在审核   | `公式情報確認中`               | 若有旧正式事实，保留其年份与确认日；候选值不公开       |
| 上一年信息可供参考         | `前年度情報`                   | 放入独立参考区，写明年份；当前年度主事实区仍待公布     |
| 当前字段不适用             | `対象外`                       | 说明不适用的资格、等级、实施方式或机构维度             |
| 筛选无结果                 | `一致する資格が見つかりません` | 保留已输入条件，提供清除与浏览全部                     |
| 正式事实读取失败           | `情報を取得できませんでした`   | 提供重试/其他页面；不回退到测试数据                    |
| 来源核查失败但正式事实可读 | 最近正式值＋`公式情報確認中`   | 明示最后成功确认时间，不把它称作本次更新               |

## 5. 页面详细方案

### 5.1 首页 `/`

**用户任务**：搜索一项资格，或直接查看日程、比较和真实官方变化。首屏结构为左侧定位和搜索、右侧可信度说明；手机按此顺序纵排。主标题沿用 `資格試験の公式情報を、わかりやすく整理。`，说明句不声称本站是官方机构。

```text
Header
定位标题 + 搜索框 +「試験日程を見る」+ 资格快捷入口 | 事实如何核验
近期重要日程（有已批准事件）／日程页入口（无可发布事件）
六项资格卡 → 日程/比较/更新工具入口
最新官方变化（有真实变化）／更新中心入口
来源与可信度说明 → Footer
```

- 搜索提交到 `/shikaku/?q=`；输入 Label 常显；快捷资格只能称 `主な資格`，除非有真实热度指标，不能称“最热门”。
- 近期事件按 JST 当前时间与已批准精确日期选取，按日期升序；每项含资格、类型、日期、确认日、来源。没有事件时显示日程页入口，标题不得暗示存在“即将发生”的事件。
- 六资格卡在有事实时可增添“下一重要事件”；无事实时仅显示身份、状态与概览入口，不出现虚构摘要。
- 最新官方变化最多展示少量真实记录并链接 `/updates/`；没有记录时用入口说明替代空白新闻卡。不得把页面样式变更视为官方更新。
- 首屏搜索和主要日程入口周围不放广告。

**验收 H-1**：360px 首屏不横溢；搜索可键盘提交；无可发布日程和更新时无日期、倒计时或变化示例。

### 5.2 资格目录 `/shikaku/`

**用户任务**：通过正式名称、别名或领域找到资格并进入详情。页面顺序：标题与范围说明 → 搜索 → 条件/结果数量 → 资格结果 → 数据来源说明。已实现的名称搜索优先打磨；多维筛选只有在数据字段、查询与 URL 契约完成后上屏。

- 搜索结果头显示 `検索結果 N 件` 与当前查询；空查询显示全量数量。清除操作回到 `/shikaku/`。
- 卡片主标题为正式名称，别名次之；可信状态位于卡片上半区，详情入口清楚可见。日程、申込み、試験内容、合格率为次级链接，数量过多时可在卡底做“相关页面”组，但不能产生 44px 以下的拥挤触摸目标。
- 后续筛选按领域、资格类别、频率、报考条件、费用、月份、开放状态和公布状态分组；只有有可信数据的字段才开放。桌面约 280px 侧栏，手机底部抽屉；应用后显示可移除条件 Chip 和结果数。
- 参数页遵守既有 `noindex,follow` 与 canonical 规则；筛选和分页保留条件，不制造可索引空页。

**验收 D-1**：长正式名称与 FP 多维别名完整可读；空结果可清除；状态不会由卡片边框颜色单独表达。

### 5.3 资格综合页 `/shikaku/{slug}/`

**用户任务**：在最少滚动内判断“当前年度情况”和接下来该看哪项细节。建议采用标题/状态区 → 年度切换 → 快速事实 → 分主题解释 → 来源与历史 → 相关资格。桌面主内容约 800px、侧栏约 320px，手机回到单列。

- H1 为资格官方名称；别名及类别为辅助信息。标题下就地显示可信状态、业务状态和 `公式情報確認`。侧栏不重复同一状态；手机年度切换位于事实之前。
- 快速事实优先：报名截止、考试日、合格发表、费用、报考条件、考试方式。每项仅在该字段有已批准数据时显示值；待公布时显示明确状态。等级、实施机构、方式和考试组成等维度紧邻值。
- 事实卡后的解释区先说明资格和当前年度，再展示报名、内容、合格率等入口。来源模块保留在主内容列，不能因长侧栏留出大段空白。
- 官方来源与验证历史分开；每条事实的来源展开仍需独立可用。页面级验证时间不能替代事实级时间。

**验收 Q-1**：手机端标题、状态、年度与第一组关键事实顺序正确；上一年度事实不进入当前年度的主值。

### 5.4 年度页 `/shikaku/{slug}/{year}/`

**用户任务**：确认该年度每个关键节点并添加日历。H1 应包含资格名和年度，而不仅在正文写年份。顺序：状态/变化通知 → 年度时间线 → 事件详情与 ICS → 官方文件 → 来源与历史。

- 时间线按“申込開始 → 申込締切 → 試験日 → 合格発表”等实际获批事件排列；同日多事件不能合并为单一事实。日期显示日本格式与星期；精确时间和时区只在来源明确时显示。
- 当前或最近的已批准事件可以加强边框；过去节点保留可读。订正/延期使用独立警示及“旧 → 新”说明，指向官方来源。
- 单事件 ICS 贴近事件，全年 ICS 置于时间线末尾或标题操作区；无精确日期则隐藏下载，不能生成空或推测事件。
- 未达到年度页发布条件时不生成只有“未公布”的薄页；沿用资格综合页中的待公布说明。

**验收 Y-1**：多个年度可切换且当前年明显；无精确日期不出现倒计时和 ICS；历史年度显著标注。

### 5.5 报名与条件页 `/shikaku/{slug}/application/`

**用户任务**：判断能否报名、如何报名、应准备什么。顺序：当前申请状态/期限 → 官方报考条件 → 申请方式与步骤 → 材料和费用 → 常见遗漏 → 官方报名入口 → 变化与来源。

- 报考条件以官方原意为先，解释单独标为编辑说明；不得把不同资格的 `受験/受検`、`申込み/受検申請` 强行改成同一术语。
- 申请步骤使用编号列表；材料使用检查清单；资格/等级差异用小标题或表格，不把多维条件压成一句话。
- 官方报名入口是明确外链，和本站说明分隔，附近不放广告。报名未开放或结束时不使用主色“立即报名”样式。

**验收 A-1**：条件、费用与报名入口均可追溯；用户不会把本站按钮误认为官方提交表单。

### 5.6 考试内容页 `/shikaku/{slug}/exam-content/`

**用户任务**：看考试方式、科目、题量、时长、合格标准与免除。顺序：考试概览 → 科目结构 → 时长和形式 → 评分/合格标准 → 免除 → 官方大纲/样题 → 制度变化与来源。

- 一组科目用同一表格或并列模块展示，列名含等级、科目、题量、时长与形式；数据不齐时按字段标状态，不删整行。
- 专业术语可用简短解释，但解释不得增加未经批准制度信息；禁用难度星级或“容易通过”的主观判断。
- 官方样题和大纲链接与来源标识分清，避免用户以为站内解释就是官方文件。

**验收 E-1**：长科目名称与多等级结构在手机可读；未知合格标准不显示 `0`、`-` 或臆测值。

### 5.7 合格率页 `/shikaku/{slug}/pass-rate/`

**用户任务**：读取最新年度指标并理解趋势和统计口径。顺序：最新获批年度与数值 → 分母和统计口径 → 历年趋势 → 年度数据表 → 解读边界 → 逐年来源。

- 最新指标与历史年度分区。若官方分母为实际受考人数，明确写出；官方使用其他口径时保留原口径，不自行替换。
- 图表须有标题、年度范围、单位、文字摘要和等价数据表；缺少足够历史数据时只显示表格，不硬画趋势。
- 明示“过去合格率不代表个人通过概率”；等级、机构、考试方式不混算。

**验收 P-1**：图表/表格数字一致，所有年度有来源；缺失年份不插值。

### 5.8 跨资格日程 `/schedule/` 与未来年度路由

**用户任务**：按年度、资格和事件类型查日期并导出 ICS。现阶段以时间线列表为正式视图；未来月历和表格视图在事件数据、筛选与 URL 契约齐备后补充。手机默认时间线。

- 筛选区顺序为年度、资格、事件类型（未接入前不展示）、应用/清除；结果头显示事件数量。改变条件后应保留可理解的筛选状态。
- 节点按日期升序。事件类型使用文字＋语义色：开始信息色、截止警示色、考试主色、发表成功色、变更/暂停危险色。每个节点显示来源、确认日和资格年度页入口。
- 月历视图未来不得成为唯一视图；跨月多事件仍须可键盘到达。手机不强制缩小整个月历。
- 单项 ICS 只在精确日期存在时显示；资格全年 ICS 仅在年度与资格均确定且有获批事件时显示。

**验收 S-1**：空列表清楚说明；多个事件与长值不互相覆盖；JST 解释一致。

### 5.9 比较器 `/compare/` 与比较指南

**用户任务**：选择 2–3 项资格，以统一维度核实差异。顺序：选择区 → 选择数量与必要提示 → 核心差异摘要（有足够批准事实时）→ 完整比较矩阵 → 来源说明 → 相关比较指南。

- 选择卡整体可点击，选中态用复选框、边框、背景和文字同时表达。选择少于 2 项不渲染空矩阵；超过 3 项明确提示并阻止或裁剪规则须与实际行为一致，不能仅在帮助文案里说明。
- 矩阵维度至少覆盖性质、机构、报考条件、费用、频率、方式、时长、合格率与下一事件，按已有可靠字段逐步开放。不同年度/等级/机构的事实不可假装同口径；单元内列出维度。
- 桌面表头、维度列保持可辨；手机优先考虑“逐维纵向卡片”，在实现前可使用局部横向滚动，但页面本身不能滚动。滚动容器要有“横にスクロールして比較”提示。
- 静态比较指南解释选择维度，动态矩阵展示事实；不得只凭合格率下“更容易/更值得考”的结论。

**验收 C-1**：三项资格、长条件及缺失值都可读；来源、年度和维度贴近单元值。

### 5.10 更新中心 `/updates/` 与未来更新详情

**用户任务**：弄清哪项官方事实改变了、何时改变、影响哪里。列表只收录已批准的事实变化，按本站反映时间降序；页面检查、样式改动和普通文章发布不进入列表。

- 卡片顶部为类型、资格和字段；中部显示旧值/新值或首次发布值；底部为官方确认日、官方来源、受影响页面。时间标签应区分官方发布日期与本站反映时间。
- 变更/订正优先使用左侧风险边线与文字，不把整卡涂红。若缺少旧值，使用 `公開値`，不显示虚假的“変更前”。
- 未来详情页需补充官方原文摘要、实际影响、版本链和相关页面；在路由未完成前，列表仍链接到受影响资格年度页。

**验收 U-1**：无真实变化时出现诚实空状态；变化前后长文本在手机上下排列且不截断。

### 5.11 指南、可信度与政策页

已有 `/guide/` 与比较指南采用编辑型模板：面包屑 → 标题/摘要 → 正文分节 → 相关任务入口。正文最大 720px、H2 分节、列表采用语义结构。长文可添加桌面目录。解释文字与动态事实分开，最新日期/费用通过事实模块或相关资格页引用，不在文章中复制静态数字。

产品规划要求的运营者、来源、编辑、AI、广告、隐私、条款、纠错和联系页，在真实内容与路由完成前不作为可点击占位；政策页和纠错页不放广告或营销主操作。纠错表单只收集必要信息，成功/失败有明确反馈，不显示未经审核的公开更正。

**验收 G-1**：指南链接目标存在；解释来源清楚；政策页不混入营销卡。

### 5.12 404、API 错误与不可发布页

404 显示页面不存在、资格搜索/目录/日程入口；不猜测用户要找的资格。API 错误说明正式数据暂不可读取，提供重试与安全导航；不展示内部堆栈、数据库路径、fixture 或旧候选。因未达发布条件而不可展示的年度页应回到资格综合页或给出明确状态，不生成只有占位文案的可索引内容。

**验收 X-1**：错误时主要导航仍可用；没有测试数据泄露；异常文案不把来源检查失败误写为官方未公布。

## 6. 响应式与可访问性验收

视觉检查视口为 320、360、768、1024、1280、1440px；同时检查 200% 文字缩放、键盘 Tab/Shift+Tab、焦点可见、减少动态效果和无指针 Hover。320px 全页面无横向溢出；只有比较矩阵和确实无法安全转换的数据表可在自身容器内滚动。移动固定底栏与安全区、表单、弹层、广告之间不得重叠。

重点压力样本：长资格名、长来源标题、多个状态、年度切换、FP 多机构/等级、CBT 与年度考试混合、三项比较、多个同日事件、无获批事实、上一年度参考、变化订正、API 失败。每个状态均要检查文案、颜色、来源和操作，不能只对理想满数据页截图。

目标为 WCAG 2.2 AA：正文对比度至少 4.5:1，大文字至少 3:1；页面唯一 H1、语义表头和 Caption、可读链接名、可达来源展开、结果数量可被辅助技术感知。图表必须提供文字或表格替代。广告与关键事实/官方链接至少保持 24px 视觉距离，首屏核心任务区和政策页不放广告。

## 7. 逐项实施批次与完成定义

| 批次 | 页面/组件                                        | 前置条件                                       | 交付验收                                       |
| ---- | ------------------------------------------------ | ---------------------------------------------- | ---------------------------------------------- |
| 1    | 令牌核对、Header/Footer、面包屑、页内与移动导航  | 确认现有文字品牌继续作为占位                   | 全站导航一致、无死入口、320px 不溢出           |
| 2    | Badge、事实卡、来源展开、空/错状态、事件和变化卡 | 对齐现有状态与数据契约                         | 同一事实跨页面文案和来源一致                   |
| 3    | 资格目录、综合页、四类子页                       | 已批准事实及缺失原因可区分                     | D-1、Q-1、Y-1、A-1、E-1、P-1                   |
| 4    | 首页、日程、比较、更新                           | 只发布实际可用入口；动态模块有已批准数据才启用 | H-1、S-1、C-1、U-1                             |

每批交付均需：记录改造页面与状态清单；在 360px 和 1280px 检查正常及空状态，在 320px 检查溢出；运行类型检查与相关渲染/交互测试；核对 URL、SEO、ICS、来源和事实口径无回归；保存可供复核的页面截图或明确记录无法取得截图的环境原因。未满足上述条件时该批次不标记完成。

## 8. 明确不在 UI 层决定的事项

正式产品名与 Logo、具体图标/图表库、广告供应商、统计字段口径、官方来源授权、年度页发布阈值、候选事实审批规则由各自上位规范或后续产品决策负责。UI 实施不得因视觉需要改写正式事实、补全缺失数值、自动开放未实现路由或修改审核权限。
